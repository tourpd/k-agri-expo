# 프로젝트명

K-AGRI EXPO 전시장(Booth Hall) · 업체부스 자동생성 · 슬롯배정 시스템 안정화

---

# 탄생 배경

K-AGRI EXPO 입점 신청 후 실제 전시장 부스가 자동 생성되고 전시장에 노출되는 구조가 필요해짐.

---

# 왜 시작했는가

- 업체 신청 → 승인 → 부스 생성 → 슬롯 배정 → 전시장 노출을 자동화
- 운영자 수작업 제거
- 업체가 직접 관리 가능한 전시장 구축

---

# 해결하려는 문제

- 신청은 됐는데 부스가 생성되지 않는 문제
- 슬롯과 부스 연결 불일치
- 전시장에는 보이는데 상세페이지 진입 불가
- vendor / booth / slot 데이터 불일치

---

# 기존 방식의 한계

- 신청 데이터와 부스 데이터 분리
- 슬롯 정보 수동 관리
- hall 기준 조회와 booth 기준 조회 혼재
- id / booth_id 사용 기준 불명확

---

# 핵심 철학

"신청하면 자동으로 전시장에 입점된다"

"전시장은 슬롯이 기준이고 부스는 슬롯에 연결된다"

---

# 무엇을 가장 중요하게 보는가

- booth_id 단일 기준
- 슬롯 중심 구조
- 운영자 개입 최소화
- 실제 전시장 상태와 DB 상태 일치

---

# 주요 결정사항

- hall_booth_slots가 전시장 진실 데이터
- booth_id를 부스 식별자 표준으로 사용
- slot_code 대신 slot_id 사용
- hall → slots → booth 순서 조회
- 공개 페이지는 슬롯 연결 부스만 노출
- 부스 상세는 booth_id 기준 조회

# 베이스캠프 요약

현재 펀토리 부스는 정상 생성되었고 농자재관 A1 슬롯에도 정상 연결되어 전시장 목록에 노출된다.

신청 → Vendor → Booth → Slot 배정 파이프라인은 완성되었다.

남은 핵심 과제는 /expo/booths/[id] 상세페이지를 booth_id 기준 조회로 안정화하는 것이다.

전시장 구조는 hall 기준이 아니라 hall_booth_slots 중심 구조로 확정되었으며, 슬롯에 연결된 부스만 공개 전시장에 노출하는 방향으로 확정되었다.

상세페이지 안정화가 완료되면 업체 관리, 문의, 리드, 특가, 제품 등록까지 연결되는 EXPO 운영 체인의 기반이 완성된다.
