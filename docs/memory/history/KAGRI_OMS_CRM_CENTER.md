# 프로젝트명

K-AGRI EXPO 제품 주문 운영센터(OMS) 고도화

# 탄생 배경

K-AGRI EXPO 공동구매·샘플신청·제품주문이 증가하면서 주문 상태 관리, 입금 확인, 출고 관리, 배송 관리 업무를 체계화할 필요가 생김.

# 왜 시작했는가

농민 주문을 단순 신청서가 아니라 CRM 기반 주문 운영 시스템으로 관리하기 위해.

# 해결하려는 문제

- 주문 상태 추적 어려움
- 입금 확인 누락
- 출고 관리 비효율
- 배송 상태 관리 불편
- 주문 데이터와 신청 데이터 구조 불일치
- 관리자 업무 과부하

# 기존 방식의 한계

- 신청서 중심 구조
- farmer_name, phone, address 등 과거 컬럼 사용
- 실제 주문 데이터와 화면 구조 불일치
- 주소 중심 표시
- 농민 정보 활용 부족
- CRM 확장 어려움

# 핵심 철학

주문관리 시스템이 아니라 농민 CRM 운영센터로 발전시킨다.

# 무엇을 가장 중요하게 보는가

- 엑셀형 관리자 화면
- 한 줄 한 주문
- 모바일 우선
- 실제 저장 데이터 기준 화면 구성
- 운영자가 한눈에 파악 가능해야 함

# 주요 결정사항

- 카드형 UI 사용 금지
- 엑셀형 테이블 유지
- 주소 컬럼 제거
- 지역 정보 사용
- 농민 정보 중심 구조
- 재배평수 표시
- 권장수량 표시
- 기준면적 표시
- 주문수량 표시
- CRM 확장 가능 구조 유지

# K-AGRI 전체에서의 의미

K-AGRI 거래·공동구매·브랜드관 수익화를 담당하는 핵심 운영 시스템.

# 이 프로젝트가 전체 K-AGRI 구조에서 담당하는 역할

브랜드관
↓
신청
↓
주문
↓
출고
↓
배송
↓
정산

으로 이어지는 실제 수익 흐름의 관제센터.

# 베이스캠프 요약

현재 K-AGRI OMS는 기본 주문관리 기능은 완성되었으며, 다음 단계는 ProductOrderBox 실제 저장 데이터 기준으로 주문관리 화면을 전면 재구성하는 것이다. 기존 farmer_name·phone·address 구조를 폐기하고 buyer_name·buyer_phone·buyer_region·farm_area 중심의 농민 CRM 구조로 전환한다. 주소 중심 주문관리에서 벗어나 지역·작물·재배면적·권장수량 기반 운영 시스템으로 발전시키며, 최종 목표는 K-AGRI 브랜드관·공동구매·직거래·농산물거래소까지 통합 관리하는 중앙 주문 관제센터를 구축하는 것이다.
